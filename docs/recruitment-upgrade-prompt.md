## A. 开始前完整阅读

先读取目标开发分支中的 AGENTS.md、PRD.md、README.md、docs/recruitment-upgrade-development.md。PRD.md 是唯一产品需求基线，任务稿是 D00—D10 的完整执行拆解，必须逐节阅读并逐项覆盖。若本提示词所在文件尚未在远端，先从用户提供的本地仓库取得配套文档；缺文档时明确指出缺项，不凭本提示词摘要假装已读完整需求。

涉及外部请求读 docs/china-network-accessibility.md；涉及部署读 DEPLOYMENT.md 及 deploy/ 对应手册；参考 docs/final-e2e-acceptance-report.md 和 docs/m08-source-acceptance-report.md 时保留历史版本边界。修改 Next.js 代码前阅读 node_modules/next/dist/docs/ 中相关版本指南。发现其他适用目录约定也要遵守。

优先使用已有本地仓库。检查 git status、分支、暂存内容、远端和用户现有修改。目标仓库可能叫 target；origin 可能指向不同的 -project 仓库，必须按完整 URL 核实。更新远端信息，核对开发分支；有未提交用户修改时保留，不 reset/clean/stash 或混入任务提交。需要隔离时使用独立工作区。当前分支不合适则在确认的开发分支基础建立 codex/ 前缀任务分支并记录推送位置，不能强制覆盖远端历史。

## B. 本轮必须交付

以 PRD 第11节及任务稿为准，覆盖：
1. 分阶段教育经历、本硕专业独立、师范背景归属、旧值确认和安全迁移。
2. 报考资格与必须/优先/不限的求职偏好分离。
3. 逐条件匹配解释、采用的教育经历、官方证据和四档判断。
4. 多原因无结果、真实覆盖和更新状态、筛选调整前影响预览及撤销。
5. 按岗位补充资料、保存重算、返回与变化反馈。
6. 独立往年参考、年份/批次/跨年有效期、历史条件对照与证据。
7. 岗位/单位/地区学科关注、新公告关联、站内动态与透明提醒。
8. 纠错补录、本人查询、后台处理、发布修正和重新计算闭环。
9. 当年招聘/往年参考/我的关注/我的资料四个主入口及旧路由兼容。
10. 来源到用户目录的可观察性、完整验收及交付记录。

沿用燕麦可可棕视觉；保留采集、审核、证据和账号权限。真实无数据不能伪造岗位；UNKNOWN 不当 FAIL，歧义不当符合；历史不当在招；部分覆盖不称全国完整。会员价格与售卖关闭边界保持本轮 PRD 要求，不新增收费点或真实支付接入。

## C. 自动执行循环

严格按任务稿 D00、D01……D10 顺序串行实施，不把所有代码做完再补验收。每模块执行：

读取需求和实际调用链 → 写清实现差距及验收点 → 完成前后端/模型/交互/权限所需链路 → 运行自检 → 修复失败并复测 → 更新进度文档 → 检查暂存内容 → 提交 → 推送 → 确认远端提交 → 自动开始下模块。

每模块完成后不等待用户说“继续”。先前模块已有正确实现时复用并用证据验收；有实际文档/验证成果再提交，不制造空提交。将模块保持在可构建状态；入口可按开关渐进隐藏，但最终生产构建必须可达。

自检门槛：
- 前端改动运行根目录 npm run lint、相关 npm test 和 npm run build；后端改动在 backend 运行对应 lint/test/build；跨层两侧执行。
- 测试具体脚本以当前 package.json 和工作流为准。关键交互运行浏览器测试，迁移用临时真实 PostgreSQL 验证，任务用 Redis+API+Worker 验证。
- 新逻辑保留有效回归测试；失败必须修复，不能通过删除断言、skip、expected fail 或关闭 CI 达到通过。既有已知失败明确记录并评估，不得冒充全通过。
- 只提交该模块相关文件。提交前 git diff --check、检查暂存 diff 和敏感数据；提交信息含模块号及目的。不能使用无差别 git add . 混入用户工作。
- 常规提交后推送经核实的目标远端和分支；不 force push。核对远端分支 SHA 与本地提交相同，推送失败先解决，不跳到下一模块。
- 若有适用于该提交的阻断 CI，检查状态和日志；失败先修复。CI 尚在运行时可阅读下一模块和准备设计，新的模块提交前先确认上一模块 CI 结果。D10 最终必须核对最新提交 CI；无法读取时写待验证，不能宣布远端通过。

## D. 进度、阻塞和恢复

维护 docs/recruitment-upgrade-progress.md，逐模块记录需求编号、状态、修改、命令与结果、证据、提交、推送与 CI 状态、下一步。上下文不足或工具中断时写清恢复点；下一次从未完成模块继续，不重复已验收模块。每次更新只记录实际发生的事实。

普通实现选择自行解决，持续推进。只有缺凭证/权限、需求实质冲突、用户修改冲突无法隔离等确需用户决定时，说明具体阻塞和所需最小信息；安全的独立检查可继续。超时或用户未回复不视为授权。线上连续观察不要求空等7天，交付真实监测方式和待验证项。

本任务授权开发、自检、逐模块提交推送。生产部署、数据库生产迁移、合并 main、收费开放不在自动执行范围；最终交付部署准备和操作说明即可。
