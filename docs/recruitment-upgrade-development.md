# 招聘发现与报考决策升级：开发任务需求稿

日期：2026-10-28。产品基线为 [PRD](../PRD.md)，本稿负责执行拆解，不重复创建 PRD。当前状态：全部模块待核实、待开发。本稿不代表已实现。开发提示词由用户在本地另行提供，不纳入远端文档。

## 1. 执行约定

按 D00—D10 串行交付。每模块：读需求与调用链 → 确认差距 → 实现完整纵向链路 → 自检 → 修复并复测 → 只提交该模块文件 → 推送指定分支 → 核对远端 SHA → 更新进度并进入下模块。用户无需逐模块说“继续”。已有正确实现复用，用证据验收，不制造重复模块或空提交。

需求可追溯到 PRD U01—U10。每模块必须有用户行为、API/模型、权限、失败状态和验证证据；纯前端假数据不算真实交付。细分提交允许，但模块出口必须完整。依赖前序功能可先隐藏入口，最终 D10 必须真实构建可达。

## 2. 模块任务与验收

### D00 基线核查与无结果定位 → U01—U10

读取 AGENTS、PRD、README、部署及验收入口；盘点工作区、分支、远端、脚本、开关和已有实现。沿画像/API/匹配/发布目录/来源定位原始案例的无结果：浙江江苏上海、硕士、2026-06 毕业、汉语言文学师范、高中语文证。用户未说明专业阶段或证书取得状态，记录为待确认，构造测试变体而非替用户补事实。生产只读诊断需已有合法访问条件；不可访问则记录边界，用本地真实目录/固定材料复现，不假称线上根因。

交付 `docs/recruitment-upgrade-progress.md`：需求到模块映射、已实现/缺口、现有路由/状态到目标映射、测试基线、风险和后续任务。记录当前来源/发布/匹配数量时必须带环境、时间和权限范围。

出口：明确区分已证实原因和假设；确认目标远端与分支；不提交现有用户无关修改或敏感样本。

### D01 教育经历模型与兼容迁移 → U01

实施前后端教育经历契约、校验、持久化、迁移与兼容读写；稳定 ID，保留原专业和待确认归属。旧单一专业不能复制到多个阶段。研究特殊学历路径、学历/学位、预计/实际取得、师范背景和专业目录存储，复用领域模型。

出口：本科/硕士专业不同可独立保存；旧客户端不破坏新经历；迁移重复运行无重复/丢失；账号隔离、并发更新、登录合并测试通过。迁移在临时数据库验证前后数据，提供备份和恢复/向前修复方案，不在生产试验。

### D02 我的资料与分阶段填写 → U01、U05

完成初填、编辑、添加删除经历、校验、草稿、师范背景与旧值确认。首屏渐进填写；缺失可保存并明确后果，日期语义清楚。同步演示数据边界与真实 API 类型。

出口：本硕不同专业完整录入并刷新保留；保存失败不丢输入；键盘、手机可用；切换账号无串数据；未确认归属不伪装已完整。删除被引用经历时重新计算并保持旧判断记录可追溯。

### D03 资格与偏好、阶段匹配 → U02、U03

资格事实与偏好分离，必须/优先/不限影响筛选排序。实现专业指定阶段、任一阶段、多阶段同时满足、阶段未明确等规则，输出采用经历和证据。保持四档判断及三类浏览标签映射，时间闸门独立。

出口：本科符合硕士不符在三种明确公告口径下各得正确结果；歧义进入人工确认，缺资料 UNKNOWN，硬条件失败 FAIL；更改偏好不更改资格。证书取得状态、应届定义、失效岗位回归通过。

### D04 结果解释、无结果与影响预览 → U03、U04

前后端完成条件解释、正文附件定位、真实覆盖与三种时间、无结果多原因、统计口径。调整预览使用同目录和画像版本，只读计算、确认保存、撤销、过期响应保护；统计按实际报考单元去重，说明口径。

出口：空目录、未覆盖、抓取延迟、网络失败、待审核、未开始、已截止、资格不符可区分；调整前后计数与实际列表一致；无权限材料不泄露。不可用数据不能显示编造数量。

### D05 定向补充与保存后反馈 → U05

复用已有补充路由、缺项计算与安全返回。字段与相关岗位关联，解释补充价值、允许跳过；保存重算并显示变化，仍未确定的条件保持原状态。

出口：详情→补充→保存→原详情完整；筛选与位置保留；登录重定向、并发冲突、失败重试、演示真实隔离通过；不强制填写与岗位无关的敏感资料。

### D06 往年参考目录与详情 → U06

新增历史查询与页面，复用已发布证据和版本，明确发布时间/批次年/有效期分类。记录历史材料状态、对照当前资料的计算时间与边界；历史过滤不能污染当前列表或计数。无数据给真实空状态，官方材料导入沿审核流程。

出口：年份地区学段等筛选有效；旧公告无报名动作；跨年仍可报岗位在当前入口可发现；失效链接可看到存档说明；缺日期不猜。历史录入操作权限及查询性能/分页检查通过。

### D07 关注对象与站内动态 → U07

区分岗位/单位/地区学科关注；稳定单位身份，模糊关联需审核。复用报考跟进状态与日程；新公告发布后关联和重算，重大变更生成幂等站内动态。提供监测范围、最后检查、通知设置和异常状态。

出口：保存历史公告不自动订阅地区；重复处理无重复关注/通知；取消关注生效；同名单位不串联；用户隔离；旧跟进状态和个人待办保留。没有外部通知渠道时只交付真实站内闭环，不伪造微信/邮件成功。

### D08 纠错补录与管理处理 → U08

复用反馈受理、纠错面板、来源流水线和审核权限。提交自动带字段，官方链接经安全校验/限流/去重；用户查自己的受理状态与原因，管理员处理并留审计。修正发布版本、重算并联动关注动态。

出口：用户A不能读用户B提交；普通用户不能处理；恶意/内网链接被拒；重复提交可识别；未审核不公开；需补充/未采纳理由可查；修正到用户结果有端到端证据。

### D09 导航整合与采集可观察性 → U09、U10

统一四入口，当年招聘/往年参考/我的关注/我的资料；保留日程材料备考等次级入口及旧链接。统一方案 B、状态文字、加载错误、返回上下文及无障碍。核查真实流水线阶段计数、异常和变更关联，补齐需求范围内的缺口。

出口：桌面手机一致，320/768/1024/1440px 无遮挡溢出；键盘焦点可用；发布构建 flags 使功能可达；缺覆盖与无新增能区分；形成连续采集观察方法与记录模板，未观察保持待验。

### D10 全项目验收、文档与交付 → 全部

全量前后端 lint/test/build、真实数据库迁移、API+Worker 冒烟、Playwright 完整用户/管理员流程、外部依赖检查。包括旧账号、新账号、游客/演示边界、无数据和异常。检查新增索引/分页避免全目录反复扫描，记录代表数据量与响应时间，不凭空承诺容量。

交付 `docs/recruitment-upgrade-acceptance.md`：逐 U01—U10 证据、命令/时间/环境/结果、真实与模拟边界、遗留问题、构建开关、迁移与恢复说明、CI 链接、提交号、线上待验项。更新 README 和 PRD 实现状态，保留历史报告不覆盖。

出口：可执行检查全部通过，既有 expected fail/skipped 有逐项解释、不增加掩盖新问题的跳过；所有模块已提交推送并核对，远端 CI 成功后才称构建通过。连续观察/外部凭证/生产验证未完成单列，不称全产品验收通过。

## 3. 每模块共同自检门槛

1. 核对 PRD 对应项与接口、持久化、权限、真实空状态、旧流程兼容；新增逻辑写能捕捉真实错误的回归测试。
2. 前端改动执行根目录 lint、相关单元测试和 build（含 postbuild）；后端改动在 backend 执行 lint、相关测试和 build。跨层模块两侧都执行；纯文档核对链接和 diff 即可。
3. 数据结构变化在临时 PostgreSQL 验证迁移，涉及来源/任务在 Redis+API+Worker 环境验证；涉及交互补浏览器测试，不以 Mock 替代真实持久化验收。
4. 任一失败先修复、复测，再进入提交。不得放宽断言、关闭阻断 CI 或将新失败改为 skip/expected fail。
5. 提交前 `git diff --check`，检查暂存文件和敏感数据；显式选择模块文件，检查提交内容后推送。推送失败解决后再进入下一模块。
6. 每模块提交内更新进度：需求编号、实现/复用、检查结果、剩余边界。提交号和远端确认在下一条进度或最终记录补充，避免记录当前提交自身 SHA 的循环。

## 4. 全局端到端场景

- 用户原始案例不预设有结果；覆盖/目录/时间/匹配每环节有解释。
- 本硕不同专业与三类阶段要求；未知、官方歧义、明确失败三种区别。
- 资料编辑→重算→结果→偏好只读预览→确认→撤销→返回。
- 历史检索→证据→关注单位→审核发布新公告→站内动态→重新判断。
- 纠错提交→本人查询→管理处理→新发布版本→相关用户结果更新。
- 旧用户迁移/登录合并/并发/跨账号，旧URL、日期跨年、撤回、失效链接。
- 断网、空数据、缺覆盖、后台故障不回退为真实 Mock；暂停 Worker 可观测且恢复后能继续处理。
