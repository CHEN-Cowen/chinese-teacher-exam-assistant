## 1. 本轮边界

- 首版是**人工触发的纵向流水线**：管理员手动提交官方 URL、粘贴正文或上传附件；不做自动全国爬虫与定时采集调度。
- 不引入 Redis/BullMQ/Kafka；异步执行用**数据库任务表 + 管理员手动处理（必要时单进程轮询）**。
- 处理对象当前仅为**语文学科**相关公告/岗位，但数据模型不绑定单一学科。
- 首轮数据覆盖 3—5 个招聘方式有代表性的地区（直接报学校、区县岗位组、录取后择校、事业编/备案制等地方用工形式）；页面必须公开实际覆盖地区、来源数量与最后更新时间，“全国”只是长期方向。
- AI/OCR 只产出候选字段与辅助文案，经后端适配器调用境内可访问服务；网络与供应商要求见[国内网络可访问性文档](./china-network-accessibility.md)。

## 2. 三层事实分离

| 层级 | 含义 | 存储形态 | 用户端可见性 |
|---|---|---|---|
| 公告事实 | 官方网页/附件原文及不可变快照 | 对象存储原件 + `SourceSnapshot` 元数据 + `EvidenceAnchor` 定位 | 作为“官方原文/来源”展示与跳转 |
| 机器提取候选 | 解析器/AI 产出的字段候选，可能有错 | `ExtractionRun` 候选 JSON + 置信度 + 证据锚点 | 只能显示“AI 提取·待审核”，不进主推荐、不参与正式匹配 |
| 人工审核结论 | 审核员确认/校正后的字段值 | `PublishedAnnouncementVersion`（不可变）+ `ReviewRecord` 留痕 | 显示“已核对”，是匹配与日程读取的唯一正式来源 |

AI 不能：直接发布高影响字段、判定用户符合资格、推测公告未写明的时间/人数/用工性质、预测录取概率。

## 3. 数据对象（后端最小模型）

| 模型 | 职责 |
|---|---|
| `Source` | 官方来源登记：发布主体、地区、入口 URL、来源类型、允许的获取方式、联系人信息、最近成功时间、失败原因、启用/停用开关 |
| `SourceSnapshot` | 每次提交/获取的原始留档：官方 URL、HTTP 状态与响应头、获取时间、对象存储地址、MIME 类型、SHA-256、与上一版本的差异指针 |
| `AnnouncementVersion` | 公告版本：所属来源、版本号、状态、发布时间、前一版本、补充公告关系、不可变结构化 payload 草稿 |
| `ApplicationUnitVersion` | 报考单元版本：单元名称/代码、地区与任教范围、学科与学段、招聘人数、组织方式、用工性质官方名称、分配方式、各项 Requirement、字段依据锚点 |
| `EvidenceAnchor` | 字段级证据：字段名、值、来源快照 id、定位类型（网页片段 / PDF 页码 / 工作表+单元格 / 附件段落）、原文摘录 |
| `ExtractionRun` | 一次提取任务：输入快照、解析器与模型版本、候选 JSON、状态、进度、错误码、重试次数、幂等键 |
| `ReviewRecord` | 审核留痕（只追加）：审核人、动作（通过/修改后通过/驳回/待确认/冲突）、修改前后值、必填原因、时间 |
| `PublishedAnnouncementVersion` | 已发布不可变版本：版本号、payload、发布时间、前序版本；用户端与匹配只能读它 |

高影响字段（至少包括）：报名开始/截止、缴费与考试日期、招聘人数、学科、学段、用工性质、报考单元、分配方式、学历、学位、专业要求、毕业身份、教师资格、年龄、户籍、社保、工作经历。**高影响字段没有 EvidenceAnchor 不能通过审核。**

## 4. 状态机

公告/提取任务主状态：

```text
submitted ──► extracting ──► pending_review ──► approved ──► published
                │                 │
                ▼                 ▼
             failed           rejected（保留候选与留痕，用户端不可见正式值）

published ──(新版本发布)──► superseded（仍可查看，不被覆盖）
published ──(取消/失效确认)──► withdrawn（用户端标注失效并通知关注者）
```

规则：

- `failed` 可重试；重试复用原始快照，幂等键防止同一快照重复出版本。
- 相同 SHA-256 内容重复提交：不创建新版本，返回已有版本。
- 自动校验（截止早于开始、人数非正、岗位代码重复、附件人数与公告合计不一致等）可拦截明显错误，但**通过自动校验不等于免人工审核**。
- 已发布版本不可原地编辑；任何修改产生下一版本；旧版本置 `superseded` 但保留查询。
- 把用户从“符合”改为“不符合”、截止提前、岗位取消等不利变更，要求双人复核。
- 补充/更正/延期/取消公告不新建孤立数据：建立与原公告的关系指针，并在新版本中记录变化字段。

## 5. 端到端流程

1. **提交**：管理员在后台粘贴 URL、粘贴正文或上传 HTML/PDF/Word/Excel/图片；URL 抓取失败时允许改为人工上传，不阻塞流水线。
2. **留档**：先保存原件到私有对象存储（开启版本控制），计算 SHA-256，写 `SourceSnapshot`；原始内容永不覆盖。
3. **解析**：
   - HTML/Excel/有文字层文档优先用确定性解析器，保留工作表、行列、合并单元格与页码位置；
   - 扫描件才调用 OCR；
   - AI 仅把已解析文本映射为候选字段，必须返回证据位置、置信度与“不确定原因”；输出做 JSON Schema 校验。
   - 未配置真实 AI/OCR 时允许明确标注的模拟提取，但候选永远停留在待审核状态。
4. **自动校验**：运行跨字段一致性检查，错误挂起到审核界面。
5. **人工审核**：左侧原文、右侧字段的对照界面；支持确认、修改、信息缺失、驳回；高影响字段逐条核对证据锚点；动作与原因写 `ReviewRecord`。
6. **发布**：审核完成生成不可变 `PublishedAnnouncementVersion` 与 `ApplicationUnitVersion`；记录与前版差异。
7. **下游消费**：
   - 匹配模块只读 published 版本，按画像即时计算四值结果；
   - 日程模块从 published 版本派生 `TimelineEvent`，以业务唯一键（公告版本 + 单元 + 事件类型）去重；
   - 新版本发布时重算受影响匹配，差异触达关注者（变化说明：什么变了、依据、影响哪些机会、是否要改报名清单或学习计划）。
8. **纠错与撤回**：用户纠错进入审核队列；高影响结论修正后发新版本并通知受影响用户；撤回记录只追加，含原因、操作人、影响范围与送达用户数。

## 6. 幂等、失败与并发

- 幂等键：快照以内容哈希去重；提取以 `snapshotId + 解析器版本` 为键；提醒事件以业务唯一键去重；所有后台任务“至少执行一次”但业务表保证结果唯一。
- 失败处理：记录短错误码与阶段，允许人工重试；重试不产生重复版本/事件。
- 并发：同一公告版本同时只允许一个审核处理人（锁或状态占位）；审核提交用版本号做乐观并发控制。
- 审计：高影响字段的发布、修改、撤回、删除申请全部留痕，只追加，不物理删除审计记录。

## 7. 收录与排除（匹配前的内容闸门）

纳入：政府/人社/教育主管部门统一公开招聘；事业单位统一招聘中的语文教师岗位；官方体系下的事业编、备案制、员额制、控制数等。
排除：民办学校、学校自主招聘、劳务派遣/外包、临时代课/兼职、无法确认官方来源的信息。
“发布在官方网站”不自动纳入——仍需判断组织主体、招聘方式与用工性质。报名截止后机会不再以“正在报名”出现；失效公告标 `withdrawn`。

## 8. 覆盖与诚实展示

- 机会页与页脚展示：已覆盖地区、有效公告/报考单元数量、最后成功核对时间、数据来源类型。
- 未覆盖地区明确提示“暂未收录该地区官方招聘信息，不代表当地没有招聘”。
- 种子/演示数据与真实公告分标：demo 环境显示“演示数据”，不得出现真实当年截止日期，不得标记为“已核对”。
- 官方外链失效时显示来源状态并提供站内留档快照信息，不静默跳转其他来源。

## 9. 界面状态要求（后台与用户端）

- 后台审核：列表（待处理/高风险/冲突/即将过期/已完成）、原件与字段对照、差异对比、发布与驳回；加载、空队列、失败、权限不足分别有明确界面。
- 用户端：来源与核对状态逐字段可见；提取失败不产生字段；审核中的候选不出现“已核对”字样；新版本未发布前用户仍看到上一稳定版本。

## 10. 实现状态核对（2026-10-05，模块 9）

第 1—9 节是设计口径；与 `backend/src/announcements/` 当前代码核对：

**已实现并测试**

- 数据模型：`Source`、`SourceSnapshot`、`ExtractionRun`、`EvidenceAnchor`、`ReviewRecord`、`PublishedAnnouncementVersion` 均已建表（迁移 `20261004120000_announcements_pipeline`）；
- 提交：`POST /announcements/sources`（管理员），入参为发布主体、官方 URL、来源类型、**粘贴正文**与 MIME；相同内容（SHA-256）重复提交命中已有快照，不产生重复任务；
- 快照留档：HTTP 提交内容写入服务端本地卷 `.data/snapshots/<source>/<hash>.bin`，记录哈希、MIME 与时间（**不是对象存储**，见下）；
- 提取：确定性解析器 `parser.ts` 产出候选字段，`snapshotId + parserVersion` 幂等键；任务支持失败重试；
- 审核与发布：自动校验 + 人工审核动作只追加留痕；高影响字段无证据锚点不能过审；发布生成不可变新版本，旧版本保留、可查差异，差异接口 `/announcements/:id/versions/diff`；
- 回归测试：`backend/src/announcements/domain.spec.ts` 覆盖发布门禁、版本只追加、高影响锚点规则。

**与设计口径的偏差（未实现，不得按已具备对外宣称）**

1. 第 3 节中“对象存储原件 + 私有 Bucket”未接入：快照在服务端本地卷，只适合开发/极小规模；
2. 第 5 节第 1 步“上传 HTML/PDF/Word/Excel/图片”与第 3 步 OCR 未实现：无 multipart 二进制上传，扫描件不能处理；
3. AI 候选提取（境内供应商适配器、JSON Schema 校验、置信度/不确定原因）未实现：当前只有确定性解析器，候选直接进入待审核队列；
4. 补充公告关系指针、双人复核锁、并发乐观控制在数据模型/部分规则层有基础，但未经过真实多人审核流程验证；
5. 流水线端到端（提交到用户端匹配变化触达）未在真实 PostgreSQL 环境跑通，状态为待验收。
