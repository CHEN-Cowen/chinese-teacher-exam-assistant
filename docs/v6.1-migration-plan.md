# v6.1 迁移计划：从 v5.2 演示原型到“机会—日程—备考”

> 历史技术/实施记录：保留当时的设计与验证语境，不作为当前需求基线。其中的阶段、章节号和未实现描述仅对应原时间；当前产品要求统一见 [PRD](../PRD.md)，架构与启动见 [README](../README.md)。旧 PRD 可从 Git 历史追溯。

更新日期：2026-10-05（模块 9 收口；模块完成情况见第 7 节）
适用范围：把 v5.2 演示版（主线“先确定考试，再安排今天做什么”）迁移为 PRD v6.1 的“机会发现 → 可解释资格匹配 → 关注与报名日程 → 主要目标 → 备考”。模块 0—9 的**代码侧工作已完成**；真实环境验收项（invited 联调 E2E、无代理国内网络冒烟）仍为待验收，不得在文档中写成已通过。

- 需求单一事实来源：[`../PRD.md`](../PRD.md)
- 技术选型依据：[`v6.1-technical-feasibility.md`](./v6.1-technical-feasibility.md)、[`technical-feasibility-sources.md`](./technical-feasibility-sources.md)
- 本文只负责**映射、处置决策、阶段完成标准与回退方式**；页面细节、数据流水线状态机、网络基线分别由另外三份文档负责，不在此复制。

## 1. 迁移原则

1. **先跑通最小可信闭环，再扩大**：模块按 0 → 0A → 1 → … → 9 顺序推进，每轮只做一个模块，验收通过才进入下一个。
2. **不推倒重写**：UI 组件、计划/反馈/重排纯函数、证据与纠错概念、Vitest 测试基础继续使用；新旧模型用兼容层并存，模块 9 才删除无调用方的旧代码。
3. **事实诚实**：演示数据显式标记；invited/production 模式不得静默回退 Mock；未实现能力不写进“已实现”文档。
4. **当前只开放语文学科**：类型、枚举与页面文案保留多学科扩展位，但不实现其他学科匹配与备考。
5. **不增加本轮边界外的基础设施**：不引入 Redis/BullMQ、Kafka、Elasticsearch、向量数据库、Kubernetes、自动全国爬虫、短信/微信推送。

## 5. 阶段、完成标准与回退方式

每阶段的“完成标准”是进入下一阶段的硬门禁；未达标不进入下一模块。回退以“上一个通过验收的提交/部署”为单位，数据层变更必须可重复执行并提供回滚。

| 阶段 | 范围 | 完成标准（验收门禁） | 回退方式 |
|---|---|---|---|
| 模块 0 文档对齐（本轮） | 本文档组与 agent 指针 | PRD 唯一事实来源；README 清楚区分 current/target；四份新文档分工不重复；零产品代码变更 | 文档全部为新增/改写，`git checkout` 对应文档即可；不影响运行 |
| 模块 0A 国内网络基线（2026-10-04 代码侧已完成） | 去境外运行依赖、系统字体栈、CSP 收紧、依赖扫描（`scripts/check-external-deps.mjs` + Vitest 守卫）、后端 `HOST`/`TRUST_PROXY` 与无库韧性启动、受邀部署说明与 Nginx 示例 | 干净构建不请求 `fonts.googleapis.com`/`gstatic`（已验证，产物 0 命中）；核心页面禁绝境外请求后仍可用（本地生产冒烟 100 请求全同源）；允许域名清单落档；无代理国内家庭/手机网络冒烟记录 | 前端改动独立成提交，回退该提交恢复 CSP/字体配置；不涉及数据迁移。**唯一剩余门禁：域名/ICP/境内 ECS 落地后的真实网络冒烟（当前状态：待验证）** |
| 模块 1 领域模型与演示数据 | 新类型、四值匹配骨架、六类 seed、纯函数测试 | 四种匹配结果、缺失≠不符合、已截止不推荐、版本不覆盖等测试通过；页面无需感知匹配细节 | 纯新增目录与 seed，旧代码路径不变；回退删除新目录即可，旧 localStorage 数据不受影响 |
