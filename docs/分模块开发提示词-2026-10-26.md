# 教招有据：可跨工具使用的分模块开发提示词

使用方法：优先一次复制下面的「完整自动执行总提示词」，让开发工具读取当前完整仓库、整体方案及本文全部模块，自主按顺序开发。也可每次复制「通用提示词」并附上一个模块提示词单独执行。若工具不能读取仓库，先提供所列文档及相关代码，不允许凭空重建项目。本文件生成时尚未实施这些模块。

## 零、完整自动执行总提示词（一次复制，覆盖全流程）

你现在负责「教招有据」项目的完整分模块开发。请实际读取方案并持续执行，不要只给开发建议或停留在任务拆解。目标仓库为 https://github.com/CHEN-Cowen/chinese-teacher-exam-assistant 。

### 1. 先完整阅读，再开始开发

请先阅读当前仓库 AGENTS.md、`docs/项目体检与商业化整体方案-2026-10-26.md`，以及 `docs/分模块开发提示词-2026-10-26.md` 的全部内容，特别是通用要求、M01—M12 与统一交接模板。继续按其中指针阅读 v7.2/v7.1/v7.0 PRD、原型与国内网络基线；按需阅读 V6.1 兼容资料。修改 Next.js 前阅读当前安装版本的本地指南。

先核对最新代码、既有修改、分支及远端。方案里的历史缺陷、来源数量和测试结果是待重新核验的起点，不是当前实况。已有实现优先复用；已修复项提供证据，不重复重写。产品最新决策为：七项 High 全部优先、持续官方公告采集与更新为核心、页面采用方案 B「燕麦＋可可棕」、月卡 30 天 ¥29、季卡 90 天 ¥59、年卡建议 365 天 ¥169，手动续购，免费和会员共享事实与资格判断标准。

### 2. 建立执行记录与安全的 Git 基线

创建或更新 `docs/development-execution-log.md`，记录各模块待开始/开发中/自检中/自检通过/已提交/已推送/受阻状态、验收证据、提交号和远端分支。不得把代码完成写成已上线，也不得把受阻写成通过。

确认目标远端 URL 确实指向上述仓库。不能只看 remote 名字：已有 origin 可能指向带 `-project` 后缀的其他仓库。保留现有远端，不擅自改写；需要时新增明确命名的目标远端。先获取远端状态，识别当前分支关系，不在有既有修改时强行切换或重置。

默认使用一个专用开发分支 `codex/modular-development`（如已存在，先检查能否安全续用；否则建立不冲突的同前缀分支），各模块在同一分支依次推送，方便追溯。除非用户另行明确指定，不直接推送默认分支，不自动合并、不自动部署。不要用强制推送、破坏性重置或删除文件来解决分歧。保留工作区原有修改，只提交本模块明确归属的改动，不使用未经检查的全量暂存。

用户已经授权：每个模块自检通过后，提交并推送到上述仓库的开发分支，无需逐次再询问。此授权不包含生产部署、合并默认分支、破坏性数据迁移或真实扣款。推送前仍须检查暂存内容无凭证、个人资料、调试产物及无关修改。

### 3. 严格执行模块循环

按本文 M01 → M02 → … → M12 的依赖顺序执行，不擅自跳到换肤或收费。每个模块完整执行以下循环：

1. 读取模块要求及相关当前代码，说明本模块范围、验收标准和必要依赖。
2. 实现模块及必要测试、配置、迁移与文档，不搭建与现有架构重复的体系，不引入无关重构。
3. 进行代码自审：业务正确性、权限、边界输入、错误处理、数据兼容、资源消耗、国内网络依赖；涉及 UI 时检查响应式、可读性及关键交互；涉及资金时检查服务端定价、验签、幂等、补偿与对账。
4. 运行仓库要求和模块对应的检查：适用的静态检查、类型检查、构建、单元/集成测试及浏览器关键流程。测试范围按风险选择，但不能省略仓库硬性门槛。浏览器验证不能只看首页截图，要实际操作相关任务。依赖模拟和真实环境验证分别报告。
5. 若发现问题，继续修复并重新运行受影响检查，直到验收通过。不得删测试、弱化断言、跳过失败、扩大匿名权限或吞异常制造通过。
6. 使用统一交接模板记录实际结果、检查命令、未验证项及必要的运行产物位置。检查暂存差异后，创建清楚对应模块的提交，例如 `fix(M01): unify public coverage projection`。一个模块可有多个必要提交，但不得在尚未自检通过时把它标记为完成或推送。
7. 将本模块提交推送到已核验目标仓库的专用分支，检查远端该分支提交号与本地一致。日志已提交内容记录模块验收结论；推送核验结果可在下一模块或最终收尾提交中归档，避免为记录自身提交号形成无限提交循环。
8. 只有本模块自检通过且推送确认成功，才进入下一模块。每轮向用户简要报告模块、验证结果、提交号、分支和下一步；无需等待常规确认。

模块验收不能只说“没有问题”，必须有证据。推送失败、检查失败或必要验收缺失时，不允许假装成功继续后续模块。可自主处理可恢复的环境问题；若缺少账号权限、邮件/支付配置或需真实持续运行时间，应准确记录缺口，完成可独立验证的准备工作，然后在阶段门槛处停住并说明所需输入。不得伪造邮件发送、支付成功或连续 7 天运行记录。

### 4. 首阶段、页面与商业化的阶段门槛

M01—M06 覆盖所有七项 High。M07—M08 验证从官方公告发现、材料归档、证据提取、审核发布到用户匹配和变更通知的持续闭环。全国覆盖分批扩展，公开真实覆盖与缺口，不承诺零遗漏。首阶段及持续采集验收未通过，不进入 M09 页面阶段。

M09—M10 使用最终方案 B，不再采用早期青绿推荐，也不照搬效果图中的演示数据、导航或生成文字。保留 v7.2 用户流程，统一桌面和手机体验，落实资料复用、上下文恢复、变更解释和纠错处理。

M11—M12 只售卖已实现并验证的权益。优先微信官方支付，按实际商户权限实现渠道。没有资质或密钥时可以完成模拟和适配层，但不能宣称真实支付验收通过或商业可上线。不要为了完成模块擅自引入新经营主体、自动续费或真实扣款。

### 5. 全部模块完成后，再做整项目端到端自检

模块检查全部通过并推送后，针对最终集成版本重新运行整体验收，不能仅汇总过去的模块结果。以可复现的数据和测试账号验证：

- 官方来源调度 → 抓取正文与附件 → 解析与证据 → 人工审核 → 正式发布 → 覆盖投影与用户匹配；重复执行、结构变化、附件失败、暂停恢复和公告改期/撤回均有正确处理。
- 匿名首次使用 → 画像 → 三类结果 → 查看官方依据 → 定向补充重算 → 注册登录及访客资料迁移 → 收藏 → 日程 → 修改资料 → 变更提示 → 纠错状态查询。
- 免费权益 → 查看价格与覆盖 → 创建订单 → 渠道支付或明确标识的模拟 → 验签与权益到账 → 重复通知/补偿 → 续购 → 到期 → 退款与对账。真实渠道未验证时保持“待验收”，不得用模拟替代。
- 桌面和手机关键任务、键盘焦点、颜色对比度、空态/加载/错误恢复、登录与支付后的上下文连续性，以及国内网络基线。
- 越权、会话安全、输入资源限制、迁移兼容、正式发布门禁及回退步骤。所有适用的仓库检查、全量测试和构建均实际运行，外部环境限制单列。

发现缺陷就修复、回归、自审；通过后提交并推送整体验收修复。最终验证远端分支与最终本地提交一致，审查目标分支全部改动，并确认没有遗漏必须交付的未提交文件。不要将其他人原有未提交修改强行清空以追求“工作区干净”。

交付 `docs/final-e2e-acceptance-report.md`，写清最终提交/分支、模块清单、实际测试与通过/失败/待验状态、数据库和配置步骤、真实运行证据、遗留风险、上线与回退清单。若报告后又有代码修改，重跑受影响验收并更新报告。

最终向用户报告仓库与分支、最终提交号、各模块结果、整体验收结论和仍需人工/外部条件完成的项目。只有所有必要验收确实完成，才能说“全部开发与验收完成”；代码完成、模拟通过、真实持续运行通过和生产上线是不同状态。

请现在开始完整阅读、核查基线并执行 M01，之后按上述循环自主推进，不要只回复“明白”或再次输出同一份计划。

## 二、模块提示词

### M01｜公开覆盖接口与统一覆盖投影（F1、F2）

完成 F1、F2。先核查 coverage 控制器、全局守卫、服务端统计和访客静态镜像。只对精确的只读覆盖接口开放匿名访问，个人接口继续鉴权。建立单一服务端覆盖投影，区分登记、核验、近期健康和已发布岗位，并提供统计口径、更新时间和版本。访客与登录用户使用同一事实来源；失败回退明确标注时间与非实时状态。

验收：匿名能读取覆盖摘要但不能读取私人内容；新增、暂停、失败、撤回来源无需改前端即可反映；未覆盖、检查失败、暂无已发布岗位分别表达。验证缓存刷新与回退，不扩大匿名白名单。

### M02｜运行监测与持续调度（F3）

完成 F3，并确认实际调度、队列和 Worker 如何工作。历史源码取证记录仅作历史证据；线上健康由持久化运行记录、暂停状态、最近成功和下次计划共同推导。按来源周期识别超时，统一目录、健康页和 M01 的口径。补齐确实缺失的持续调度、失败重试、退避、去重及运行告警，不另建重复的调度体系。

验收：正常、单次失败、持续失败、结构变化、Worker 停止、主动暂停和恢复均有正确状态；重启不丢状态，同一任务不重复产生业务记录。提供可执行的持续运行检查步骤；不能用一次手动成功代替持续验证。

### M03｜代理协议与会话 Cookie（F5）

核查真实代理拓扑和可信代理边界，修复公网 HTTPS 经内部代理后协议丢失的问题。不得原样信任任意客户端转发头。正式环境会话具备 Secure、HttpOnly、适当 SameSite，保留明确的本地开发例外，并验证跨代理登录、退出与会话失效。

验收：可信 HTTPS 链路 Set-Cookie 符合要求；伪造转发头不能绕过安全设置；正式 HTTP 入口不能暴露不安全登录。没有真实环境时提供部署验证脚本/步骤，并明确该项未在线上验证。

### M04｜Excel 解析资源边界（F6）

在保留现有未提交解析改进的基础上，修复稀疏与异常表格的资源消耗。优先按实际单元格地址处理，避免巨大矩形空扫描；对访问次数、跨度、解压规模和任务时长设置合理边界，必要时采用可真正终止任务的进程隔离，不用同线程 Promise 超时假装能中断 CPU。超限明确转人工处理，记录可理解的原因。

验收样本：普通岗位表、两个远距离非空单元格、全空虚大 !ref、合并单元格、异常压缩与超预算文件。记录耗时/资源证据，确认正常表格提取和表头识别无回归。

### M05｜注册、登录与账号恢复（F7）

核查网关已有防护，补齐邮箱格式/长度、密码规则、认证接口限速、并发重复注册处理、邮箱所有权验证和安全找回密码。令牌限时、单次使用，敏感操作正确失效会话；避免账号枚举和未验证邮箱账户接管。订单未来绑定稳定 userId，管理员权限与会员权益分离。不得因邮箱服务尚未配置而伪装发送成功。

验收：非法输入、暴力尝试、并发重复注册、过期/重放令牌、未验证邮箱恢复、密码更新后旧会话、访客资料迁移均有覆盖。缺少邮件服务配置时保留受控状态并列出配置步骤，不提交真实凭证。

### M06｜关键流程与发布质量门禁（F4）

在 M01—M05 修复基础上，归类并修复当前端到端失败，恢复正式镜像发布的阻断门槛。不可把历史“13 个失败”当作当前结果。至少覆盖匿名匹配、登录迁移、定向补充重算、审核发布进入匹配、公告延期/撤回影响、日程去重和移动端。区分演示与正式发布。

验收：关键测试失败时正式发布确实被阻断；成功路径可复现。测试不依赖随时变化的外部网站，数据回放和真实采集验证分别运行；输出真实结果及环境限制，不用 continue-on-error 隐藏失败。

### M07｜公告材料、审核、变更与发布闭环

依赖 M01—M06。复用现有采集/对象存储/标准化/审核/发布体系，补齐实际缺口，打通发现公告→正文与附件快照→解析与证据→人工审核→发布版本→用户匹配与变更提示。保留原始链接、抓取时间、内容指纹和历史版本；处理附件失败、撤回、延期、重复公告和审核退回，避免旧版本覆盖新事实。取消与改期优先提示，人工审核权限不能绕过。

验收：至少完整跑通一批真实官方公告的全链路，重跑不重复发布，失败可定位、可重试、可回退；未审核候选不能进入正式用户判断。证明一条已发布公告变更如何影响收藏、匹配和日程。

### M08｜全国扩源框架与持续运行验收

依赖 M07。先逐一核验现有来源，按统一适配契约和官方来源台账扩展；全国是分批推进目标，不要求一次宣称全国完成。每来源登记地区、栏目、访问规则、调度、负责人/处理入口、最近成功、材料与发布状态。优先完成南京/丽水独立对账：独立构建分母，区分栏目发现、正文、附件、解析和发布，不以同一抓取器输出充当独立对账。

验收：提供逐来源验收矩阵、漏采/错采清单、修复记录及持续运行报告。建议至少连续 7 天观察，具体窗口记录来源周期；不足时间则交付可重复检查方案并保持“待持续验收”，不得伪造经过时间。线上展示实际覆盖和缺口，抓取失败、结构漂移与超时可告警。阶段结束汇总七项 High 与数据闭环是否真正通过，未过不进入页面阶段。

### M09｜方案 B 视觉基础与页面壳层

依赖首阶段及 M08 验收通过。使用整体方案 12.6 的最终视觉选择「燕麦＋可可棕」和 `docs/design/方案B-燕麦可可棕-2026-10-26.png` 作为气质参考，不将生成图中的示例数据导入正式系统，不逐像素照抄其布局。先对照 v7.2 原型与既有导航，再统一语义 Token、基础组件、响应式壳层、按钮、表单、标签和焦点态。

色板：背景 #F8F4EE，表面 #FFFFFF，品牌 #735544，弱强调底 #EFE6DD，主文字 #332E2B，次文字 #766D65，点缀 #70816A。取消蓝紫渐变，不做旧、不加纸纹，不开发多主题切换。品牌色与资格状态分开，所有状态保留文字和图标。

验收：普通文字对比度至少 4.5:1，大字号至少 3:1；控件及焦点按适用要求验收，浅色辅助文字必要时加深。手机、桌面、键盘与减少动效可用。不得为了换肤破坏匹配、审核或路由流程。

### M10｜2C 页面与个人报考体验

依赖 M09。按 v7.2 任务流程优化访客首页、画像、三类结果、岗位详情、定向补充、我的报考、日程和覆盖范围页。访客看到价值与真实覆盖，回访者直接继续岗位、待办和变更；保留现有收敛导航，不照搬示意图增加入口。桌面可比较、手机可操作，优先展示截止、关键条件、官方依据及下一步。

落实资料只填一次、登录后迁移、补充只问缺项、修改后解释影响、操作后回原上下文、保存反馈和失败草稿。区分未覆盖/无已发布招聘/资格不符/网络故障；纠错提交后有编号、状态和结果，不虚构人工响应承诺。

验收：覆盖正常、空态、加载、失败、审核中和过期状态；走查找到截止、复述依据、补充重算、保存继续和纠错查询。用真实任务评估，不以截图漂亮作为通过标准；回归 M06 关键流程。

### M11｜免费权益、限期会员与价格透明

依赖 M10。依据整体方案第 7、11 节实现免费/会员边界和独立权益模型，不把 User.role 当会员状态。30 天 ¥29、90 天 ¥59（主推）、365 天建议 ¥169，手动续购、不自动扣款；年卡上架以持续服务及商业确认就绪为前提，未就绪可配置关闭。三个付费期限共享同一组已上线软件权益。

免费保留公告与来源、基础预筛、不符与不确定项、定向补充、基础收藏、站内日程和重大变更提示，不收回已有权益。多方案、批量管理、对比、导出及离站通知仅在实际实现并验收后才能售卖；先盘点已有实现，提出明确权益矩阵，次数/成本边界未确定时不擅自捏造配额或宣传无限。

完成价格页、我的会员和到期状态；付款前显著显示一次实付、天数、权益、覆盖、限制及售后。到期保留个人资料与历史成果。权益在服务端执行，并支持未来支付幂等发放。

验收：免费/有效/到期/续购边界、跨设备刷新、越权 API 请求和数据保留；折合月价不能冒充当次扣款额。没有已验收收费价值时保留关闭售卖，不用占位权益先收费。

### M12｜微信支付、退款、对账与上线验收

依赖 M11。首发微信官方通道，按实际获批权限选择 PC Native、微信内 JSAPI、微信外 H5；不得假定权限齐全。Stripe 后置，不为接入擅自新增境外主体。实现前查当前官方文档及 SDK，不沿用过期接口。缺少商户资质/证书/域名配置时继续完成可测试的适配层和模拟验证，明确真实支付受阻项，禁止伪造开通。

实现价格版本、订单、支付尝试、渠道交易、回调事件、会员权益、退款与对账。服务端定价；回调精确验签并核对商户、订单、金额和币种；事务内幂等记账和发放。回跳不作为支付凭证。专用回调路径使用渠道认证，不整体放开匿名访问。按最小范围调整 CSP、网络域名和回调部署配置，密钥仅服务端保存。

验收重复/乱序通知、超时后成功、支付成功权益失败补偿、主动查单、关闭页面、续购叠加、到期、退款成功/失败、部分退款权益策略和账单差异。退款规则未确认前不得自动臆造扣权益算法或开放不受控部分退款。提供测试证据、配置清单、对账处理入口和回退方案；真实小额验证须另获明确授权。商业上线须等 High、持续采集、权益、支付与售后均通过，不以模拟支付通过宣称商业可上线。
