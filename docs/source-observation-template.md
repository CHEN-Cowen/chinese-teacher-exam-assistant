# 来源采集连续观察记录模板

对应 `PRD.md` 第 5 节的持续验收要求：来源接入后至少连续 7 天真实观察，每日记录健康与异常处置；窗口不足保持待验。本模板供运营/开发在真实部署环境记录使用，不代替自动化指标。

## 使用方法

1. 环境：记录部署环境（standalone/开发分支）、镜像或提交号、数据库与 Redis 状态。生产观察只读管理端页面，不做破坏性操作。
2. 时间：每日固定时间（建议早上）打开 `/admin/sources` 与 `/admin/pipeline`，把「统计生成时间」一并记入，避免事后补记。
3. 判读：区分三类现象，不得混写——
   - **覆盖缺口**：来源未登记、来源降级/结构变化/受限（管理端总览卡 amber 提示）；
   - **无新增**：检查正常但最近 24 小时无新增快照（不算采集故障）；
   - **采集异常**：队列积压增长、Worker 停止、解析/提取失败率上升、连续失败。
4. 处置：异常记「现象 → 判断 → 动作 → 结果」，动作只写实际执行的（如暂停来源、手动检查、修适配器），不预填计划。
5. 结论：第 7 天汇总后才能写「连续 7 天观察完成」；不足 7 天保持待验。
