# 全国全学科与公告 RAG：开发实施方案

日期：2026-11-05。状态：待实施。产品要求以根目录 PRD.md 第 12 节为准；本文只定义实施方法，不新增并行 PRD。执行入口见 [开发提示词](all-subject-rag-developer-prompt.md)。

## 1. 交付目标与责任

交付全学科业务闭环、官方材料入库与公告级问答、地区政策检索与首批扩源、模块自检及最终真实端到端报告。全国是产品支持范围，覆盖是经逐来源验证的数据范围，两者分别展示。

用户已要求模块完成自检后提交、推送并继续，执行工具可在专用开发分支逐阶段推进，无需每阶段重复请求批准。Git 推送授权不包含合并默认分支、修改分支保护、生产部署、生产数据库迁移、付费采购或创建供应商账号。发现真实权限限制时如实报告。

## 2. 架构与接口边界

沿用 Next.js 页面及同源代理、NestJS API、Prisma/PostgreSQL、Redis/BullMQ、独立 Worker、现有原件存储及审核发布链路。新增 pgvector；实施前核实实际 PostgreSQL 扩展权限、镜像、磁盘和备份条件。通过增量迁移安装扩展与建表，隔离环境先验证旧库升级；不能替换现有数据库卷。

模块以职责划分，优先并入已有合适目录：

| 职责 | 输入与输出 |
|---|---|
| subjects | 标准字典、带上下文别名、用户/岗位/证书学科关系；未知进入审核 |
| knowledge | 文档版本、片段与原文定位、索引任务、有效性与访问范围 |
| ai | Embedding、Rerank、生成调用；凭据、超时、错误和用量处理 |
| qa | 范围过滤、混合召回、重排、上下文、回答校验、引用和反馈 |

首版用简单服务组合，不引入 Dify、LangChain、独立向量库或额外微服务作为前置条件。未来因实测瓶颈再增加组件。

### 2.1 建议数据增量

具体字段映射由 W0 核对现有模型后固定，复用已有来源、快照、发布版本和用户对象。

- Subject：稳定 code、名称、分类、启用状态；Alias：原名、学段/地区等适用上下文、映射目标及审核来源。别名允许歧义，不靠全局字符串替换决定资格。
- 岗位关联多学科并保留原文；用户意向与证书学科分别存储；历史数据沿用原始含义。
- KnowledgeDocument/Version：官方来源和原件关联、公告/政策类型、地区、适用期、版本、指纹、审核与公开状态、有效性、被哪些条款修改/替代。
- KnowledgeChunk：文档版本、关联岗位、正文、标题、页码/工作表/行号/段落锚点、公共备注关联、索引版本；向量与模型/维度绑定。
- IndexJob：状态、幂等键、尝试次数、错误分类、时间、计数；优先复用已有任务跟踪机制。
- QaAnswer：范围、材料/模型/提示词/索引版本、引用、生成状态、用量与脱敏追踪；按产品需要最少保存问题内容，配置保留期。Feedback：答案标识、问题类型、处理状态，沿用纠错权限。

引用定位与权限来自数据库，模型不能生成可被当作事实的任意链接。跨版本引用需保持可追溯，同时公开问答使用当前有效材料。

### 2.2 建议接口契约

接口名可适配现有风格，W0 固定后记录；前后端共同使用契约。

| 接口 | 关键约束 |
|---|---|
| GET /subjects | 稳定编码、启用状态和分类；供所有学科选择入口复用 |
| POST /admin/knowledge/documents | 管理权限、官方来源信息、文件限制；返回文档及异步任务标识 |
| GET /admin/knowledge/documents/:id | 分阶段状态、失败原因、可重试动作 |
| POST /admin/knowledge/documents/:id/reindex | 管理权限、去重与并发限制；审核/公开独立处理 |
| POST /announcements/:id/questions | 问题、可选岗位和会话；服务端重新确认范围与权限 |
| POST /qa/answers/:id/feedback | 可见答案及提交者权限、限流；不能借 ID 查询他人数据 |
| POST /knowledge/questions（W5） | 地区、年份、材料类型和问题；范围不明确先澄清 |

答案至少含 answer/status/citations/needsOfficialConfirmation/generatedAt，引用含真实文档版本、原文片段及位置。错误区分超时、额度/限流、未索引、无可用材料和权限不足；无答案属于正常结果，不伪装成成功生成。

### 2.3 入库与检索实现

入库：原件快照 → 解析 → 结构与引用定位 → 人工审核/发布 → 切分 → 向量化 → 索引就绪。允许提前生成内部索引，但公开查询必须同时满足审核、公开、有效及索引就绪条件。

正文按条款切分；表格每行带表头、合并单元格继承结果及公共备注。资源预算和异常文件处理复用现有解析防护。初始片段长度可以 500—1000 中文字符试验，最终由样本决定，不打断关键否定、例外或适用范围。

查询：确定范围 → 权限/有效性过滤 → 向量与关键词分别召回 → 去重融合 → 重排 → 关联必要上下文 → 生成 → 校验引用及关键结论支持 → 返回。召回量和重排数可从 30/10 的实验配置起步，通过评测调整；这不是质量保证。中文精确代码检索与中文分词分别验证，W0/W3 记录选定方案，不默认依赖英文全文索引。

pgvector 初期选择精确或近似检索需按数据量评测；近似索引下验证地区、权限过滤后召回，不因过滤少返回就跨范围补材料。SQL 使用参数化查询。索引重建使用新版本，完成后切换；旧任务晚完成不能覆盖新索引。

## 3. W0—W5 任务与自检

### W0：基线与可执行盘点

1. 读取 AGENTS、PRD、README、当前验收、国内网络与部署手册。记录 HEAD、分支、远端、工作区状态和已有未提交文件归属；对历史部署记录冲突以当前环境证据为准。
2. 检索语文/Chinese/subject 等硬编码，追踪资料 → 解析 → 审核 → 发布 → 引擎 → 列表/历史/关注全部调用链，读取真实字段与测试。
3. 核对模型服务候选的官方文档、境内接入点、账号可用模型、向量维度、费用预算、条款与密钥配置。若缺凭据，列入外部阻塞但继续独立任务。
4. 盘点真实材料格式、原文定位能力、现有错误/权限/任务机制；核对数据库扩展条件和迁移路线。
5. 建立阶段台账、样本清单、变更文件/接口/迁移清单、当前基线检查结果、W1 初始任务；确认专用 codex/ 分支不混入已有改动。

自检：清单能对应实际文件；命令来自当前脚本而非猜测；风险有处理策略；需求到阶段可追踪。提交文档后推送并核对 CI，随后进入 W1，不止步于规划。

### W1：全学科业务闭环

实现字典与种子、别名/未知审核、岗位多学科、意向与证书独立字段、兼容迁移。贯通前后端校验、画像/补充、解析审核、发布、规则、结果、历史、关注及演示；默认选择符合 PRD。

自检：语文旧流程回归；数学、英语及至少一个需特殊处理的综合/专业课样本；同名跨学段、未知、岗位多学科、证书不符、专业不符；旧资料升级及重复迁移；刷新返回与移动端筛选。使用真实公开材料验证新增学科，模拟样本单独标注。运行受影响测试、前后端必需检查和本阶段浏览器流程。

### W2：知识文档与索引

实现文档/版本/片段存储、管理员导入与状态、现有材料关联、任务去重/重试、向量服务适配、索引切换和撤回。建立 pgvector 迁移和隔离部署配置，原件沿用现有接口。配置文件只提交无密钥模板。

自检：HTML、文字 PDF、Word、Excel；表头/合并单元格/备注/页码；扫描件人工回退；重复导入、失败重试、并发、旧任务迟到；嵌入维度与模型不兼容；未审核/撤回材料不可公开查询；空库和旧库增量迁移与恢复演练。真实 Embedding 成功证据单列，缺密钥时本阶段外部联调保持阻塞。

### W3：公告级有依据问答

实现混合检索、融合与重排、上下文边界、问题范围、多轮追问、答案及引用契约、必要的后端校验。详情页增加问答、引用查看、错误恢复及反馈。为专业代码、岗位代码保留精确召回；生成服务与检索服务可分别失败并如实返回。

自检：正确答案与原文对应；岗位 A/B 条件隔离；不同年份/地区不混用；表格公共说明被带入；无答案、冲突、文件缺失、取消/延期；伪造引用、文档指令注入、追问改范围；超时/限流/额度不足；键盘与移动端。实际供应商完成向量、重排和生成全链路，记录脱敏请求标识、模型、耗时与用量。

### W4：整体加固与受控验收

修复 W1—W3 集成问题，覆盖多角色、版本撤回、任务恢复、请求预算与日志；验证问答关闭或供应商故障时原有招聘闭环可用。维护部署配置、健康语义及回退手册，在隔离环境执行完整真实后端流程；只有明确获准时才操作生产。

自检：访客/用户 A/用户 B/管理员；越权和横向 ID 访问；索引完成后再撤回/改权限；缓存清理；任务失败与服务重启恢复；真实浏览器跨页面流程；前后端全量必要检查。现有 expected failure/skipped 明确列出，不能借此隐藏本轮失败。

### W5：范围明确的政策检索与首批扩源

在地区/年份/适用范围明确的入口实现政策问答，关联政策适用对象和有效期；公告与政策冲突应同时展示并建议核实，不机械认定最新或更高层级文本必然覆盖具体招聘条款。

W0 建立扩源积压，按真实可访问来源分批执行。首批至少完成一个现有覆盖之外、公开可访问且允许采集的官方来源，并提供发现、抓取、解析、审核、发布及匹配/问答证据；受源站限制时换合适来源，仍不可达则记录阻塞。行政区划选择支持全国，覆盖展示仅反映实测来源，不能把一个城市计为全省完成。

自检：跨公告检索范围、政策年份/适用对象、失效/废止/冲突、无覆盖与故障区分、新来源完整材料链路；持续观察单独记录。W5 首批可验收不代表全国来源接入完毕，长期扩源积压保留。连续七天观察未满，最终报告结论必须保留待验。

## 4. 每模块提交与远端门禁

统一循环：实现 → 受影响检查 → 修复 → 必需构建/测试 → 审查本阶段完整差异及调用链 → 更新台账 → 精确暂存 → commit → push → 查询该 SHA 的 CI → 成功后继续。

- 首次推送前核对 remote、目标分支与工作流触发规则。使用专用 codex/ 分支；原工作区有用户改动时优先独立工作树，若工具权限不支持则使用保留改动的隔离策略。共享目录中的无关工作不纳入提交。
- 每个阶段可以多个小提交，阶段完成 SHA 必须可追踪；W0 是文档交付，仍执行仓库适用检查。只暂存本阶段明确路径；检查差异、冲突标记、意外删除、凭据、依赖锁与迁移。
- 普通推送；远端前进先获取并检查差异后合并/变基，冲突只处理授权范围。禁止强推、抹掉用户工作或直接推默认分支。
- 核对 CI 对应提交与实际步骤；失败修复再推送，成功前不进入依赖阶段。缺工作流触发则明确补齐适用分支或报告缺口，不能把“无运行”当绿色。
- 远端鉴权、网络或 CI 平台故障时保留本地提交与证据，报告阻塞，不冒充推送通过；可继续不依赖该门禁的分析准备，依赖阶段等待恢复。无需为正常提交反复索要用户确认。

## 5. 最终端到端验收与报告

全部阶段之后，在固定最终 SHA 的隔离真实部署上重新执行验收，使用 PostgreSQL、Redis、API、Worker、前端和真实供应商；模拟测试是补充。记录镜像 SHA、配置模式、功能开关及测试数据版本，管理员与普通用户隔离。

主链：导入真实公告及岗位附件 → 解析 → 人工审核 → 发布 → 索引 → 新用户多阶段教育/证书/多学科意向 → 当前与历史筛选 → 资格解释 → 问公告及岗位条件 → 查看引用 → 关注/材料/日程 → 追加补充通知 → 重新审核、匹配与索引 → 核对答案/站内变化 → 纠错处理 → 撤回及越权验证。

至少覆盖手机与桌面、语文及新增学科、普通用户与管理员、请求失败与供应商不可用。以真实标准答案集分别统计召回、忠实度、引用、合理拒答、延迟/失败/成本；W0 固定样本及数值阈值，严禁测完再降低标准。权限泄漏、关键条件错误套用、编造引用、失效材料作为有效依据、迁移丢失为零容忍阻断项。固定阈值尚未通过时修复并保留失败历史。

最终报告保存为 docs/all-subject-rag-final-acceptance.md，包含：

1. 最终提交、远端 CI 链接和环境；W0—W5 交付 SHA 与对应检查。
2. 需求到代码/测试/证据的追踪表，逐项通过/失败/阻塞/未执行。
3. 测试命令、退出状态、浏览器步骤、脱敏截图/日志及证据路径。
4. 真实模型联通与配置版本、评测集和指标；模拟与真实证据分列。
5. 迁移升级、重复执行、恢复与应用回退证据；生产是否执行单独说明。
6. 实际地区/学科/来源覆盖、新增来源及连续观察窗口。
7. 历史遗留与本轮缺口、影响、修复建议、待用户动作。
8. 结论为“隔离验收通过”“有阻塞未完成”或“生产验收通过（仅有实际授权和生产证据时）”。

报告完成后提交推送并核对最终 SHA 的 CI。若业务代码又变化，重跑受影响验收并更新报告，确保报告指向真实被测版本。没有 Key、浏览器或真实服务时可以产出阻塞报告，不能宣称整体完成。

## 6. API 接入的人机分工

用户负责：选择供应商/账号区域，账号实名与付款，开通模型权限，批准费用预算，通过供应商控制台或安全配置渠道提供 API Key；现有已授权账号和工具可用时由开发工具完成其可执行部分。不要在聊天、文档、Git 或截图中粘贴 Key。

开发工具负责：核对官方接口文档、实现服务端适配、配置模板、错误/超时/限流、脱敏、用量记录、模拟测试、真实联通与索引/问答测试，并将供应商依赖登记到国内网络文档。已有安全注入环境变量时直接使用，不读取打印密钥值。

建议配置职责（变量名由实现固定）：AI 总开关；各能力的 provider/base URL/model；服务端 API Key 引用；Embedding 维度/索引版本；超时/并发/限流/预算；内容日志保留。首版可共用百炼服务商，但三种能力独立配置。不要假定回答模型 API 同时支持 Embedding 或 Rerank。

缺 Key 时完成代码和模拟验证，保持功能默认关闭或显示真实不可用，继续全学科等独立任务。需要真实联调时一次列出用户所需操作。真实联通必须分别验证向量、重排、生成，并核对同一向量模型处理问题与文档。开发工具无法代替账号所有者完成未经授权的实名、付费或权限审批。
