# v7.2 实施追踪表（工作包 0 基线）

> 维护规则：本表是 v7.2 迭代的唯一需求状态事实来源。每次修改产品流程、页面、接口或数据模型后，必须同步更新对应行的「当前实现状态 / 自动化测试 / Feature Flag」列。状态必须基于真实调用链核实，不允许根据文件名或原型推断为已实现。
>
> 需求冲突优先级：用户最新要求 → v7.2 PRD → v7.1 PRD → v7.0 PRD → V6.1 参考。

## 1. 状态定义

| 标记 | 含义 |
|---|---|
| ✅ 已实现 | 代码在主分支，调用链完整，有测试覆盖 |
| 🟡 部分实现 | 存在可用基础，但与 v7.2 目标行为有差距（行内需注明差距） |
| ❌ 未实现 | 主分支不存在该能力 |
| 📄 仅原型/文档 | 只在 `docs/prototypes/` 或 PRD 中存在，无代码 |

## 2. 当前五条主链路的真实路径（基线回答）

| 链路 | 当前实际路径 | 与 v7.2 目标的差距 |
|---|---|---|
| 首页 → 两屏填写 → 结果工作台 | `/`（`ff_new_home` 开=结果先行首页：主标题「哪些教师岗位，你现在就能报？」+ CTA「开始匹配岗位」；关=v7.1 价值首页）→ `/onboarding`（两屏：地区意向 → 基础资格+用工偏好）→ 访客 `/preview` / 已登录 `/opportunities` | 首页结果先行已实现（R-WP1-01 ✅）；两屏填写+用工偏好入第二屏已实现（R-WP1-02 ✅，PRD 7.4.2 字段顺序：学历→毕业时间→专业→教师资格→用工偏好）；`/preview` 偏好卡保留为调整入口 |
| 结果工作台 → 定向补充 → 重算 → 返回正确分类 | `/preview` 所有补充入口跳转 `/onboarding?from=preview`（回到基础填写流程，v7.2 明确要修复的缺陷）；`/opportunities/[unitId]` 详情页为页内 `scrollToId("supplement")` 内联补充 | 专用路由 `/opportunities/[unitId]/supplement` 不存在；`/preview/supplement/[unitId]` 不存在；无重算后回程与聚焦机制 |
| 后台发布公告 → 数据库已发布版本 → 用户匹配结果 | 管理接口 `/announcements/*`（sources、runs/:id/extract、review、publish）→ 写入 Prisma `PublishedAnnouncementVersion` → **断裂**：`opportunities.service.ts` 的 `getPublishedAnnouncements()` 只合并静态 `catalog.ts`（滚动演示）+ `real-catalog.ts`（真实台账），**不读数据库** | 发布后不重部署进入用户端的数据闭环未建立（缺 `PublishedCatalogRepository`） |
| 保存机会 → 显示一个下一步 → 日程或官方确认 | 关注/保存接口与 `/schedule` 日程页已实现；保存成功后无「一个下一步」决策卡片 | 保存后下一步（阻塞条件/72 小时节点/材料/日程/官方通知五选一）未实现 |
| 访客 → 登录 → 画像与关注迁移 | `guestSessionService` 本机画像 + 登录后 `mergeGuestFollows` 合并关注已实现 | 画像读写未统一为 ProfileRepository；无 `PATCH /profile` 字段级更新 |

## 8. 已知风险汇总

1. **数据闭环断裂是最大现状差距**：后台可发布到 DB，但用户端匹配不读 DB（R-WP3-01），WP3 前不要宣称真实数据闭环。
2. **补充回退路径**：`/preview` 当前 10 处跳 `/onboarding?from=preview`，WP2 实施时漏改任何一处都会复现缺陷；`ff_targeted_supplement` 回退目标必须是详情内联表单。
3. **双轨期口径**：`ff_db_catalog` 开启过渡期，静态演示目录只能作 Demo 回退，不得混入生产真实机会（PRD 8.4）。
4. **追踪表腐化**：本表靠人工同步；每个工作包完成时强制更新，纳入该工作包 DoD。
