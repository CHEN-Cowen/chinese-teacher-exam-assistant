# S4 南京真实闭环与四源样板验收记录

> 阶段：S4
> 开发状态：代码回放与离线测试完成；真实四源运行验收未完成
> 记录日期：2026-10-24

## 1. 本阶段范围

S4 验证南京真实历史材料闭环，并建立南京、杭州、宁波、鄞州四个来源的可回放适配器和独立对账基础。S4 不把脱敏 HTML 样本或 HTTP 200 当作真实来源已覆盖，也不把代码中存在适配器当作来源“正常监测”。

## 2. 已完成

- 四个来源均注册到 `DEFAULT_CRAWL_SOURCES`，分别绑定独立 `adapterKey`、官方域名白名单和地区代码。
- 南京栏目入口及分页入口已登记；宁波和鄞州已登记待核验入口，仍需真实栏目结构确认后才能启用正常监测；杭州入口保留待运维核验状态。
- 四个 Adapter 均覆盖列表发现、正文定位、附件绝对 URL 解析和 DOM 失配显式失败。
- 南京真实历史 HTML 与两份 PDF 完成离线材料包回放：正文、附件读取状态、字段证据均进入既有抽取链路；未把未纳入的附件声称为材料完整。
- 新增独立来源清单对账纯函数：分母来自人工冻结清单，支持排除理由、发现/访问失败/解析失败/误分类/待人工、材料完整率和召回率分子分母。
- URL 对账统一忽略页面 fragment，避免同一官方文档的 `#anchor` 被误报为未发现；查询参数仍按既有规则保留，避免把带业务参数的下载地址错误合并。

## 3. 测试结果

在 `backend` 目录执行：

- S4 四适配器、独立对账、南京真实历史回放：`6` 个测试文件，`39` 个测试全部通过。
- 对账测试覆盖固定分母、取消公告纳入、后续流程排除、重复观察不放大、失败原因保留、元数据失配、待核验不输出比例、非法清单拒绝计算。
- 南京回放使用 `tests/fixtures/golden-sources/nanjing/` 下真实历史 HTML/PDF；杭州、宁波、鄞州样本是脱敏/构造回放，不能替代官网实测。

## 4. 当前未完成与风险

- 尚未在真实 PostgreSQL、Redis、Worker 环境执行四来源完整链路：发现、抓取正文、抓取附件、抽取、人工审核、正式发布。
- 尚未完成四来源在同一明确时间窗口内的人工官方栏目对账清单，因此不能报告真实召回率、材料完整率或“正常监测”。
- 杭州、宁波、鄞州 fixture 仍为测试样本；必须分别重新保存官方栏目列表/详情/附件快照，记录 URL、抓取时间、内容指纹和核验人后才能升级来源状态。
- `SourcingController.seed` 只登记来源配置，不自动把来源标为正常，也不绕过审核发布门禁。
- 本阶段没有执行数据库迁移、部署、Git commit 或 push。

## 5. 后续进入 S5 前的门槛

1. 为四个来源各冻结一份人工栏目清单，记录窗口、排除项和未发现原因。
2. 在可用 PostgreSQL/Redis/Worker 环境对至少一条南京真实材料完成审核和正式发布回放。
3. 对杭州、宁波、鄞州完成真实栏目结构和附件获取核验；失败时保持 pending/异常，不伪造成功。
4. 由独立清单计算真实指标后，再决定来源状态是否可设为正常监测。
