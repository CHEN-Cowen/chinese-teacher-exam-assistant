# 可直接交给开发工具的执行提示词

以下全文可作为开发任务输入。配套实施方案需与项目一起提供；PRD.md 是唯一产品需求基线。

---

你现在负责在当前“教招有据”仓库内实际完成全国全学科与官方材料 RAG 问答升级。请执行开发，不只输出计划。连续完成 W0—W5，每阶段自检、提交、推送、核对远端 CI 后进入下一阶段，最终执行整体端到端验收并交付报告。

## A. 首先读取并确定基线

按顺序读取 AGENTS.md、PRD.md（重点第 12 节）、README.md、docs/recruitment-upgrade-acceptance.md、docs/all-subject-rag-development-plan.md。外部服务读取 docs/china-network-accessibility.md；部署配置读取 DEPLOYMENT.md 和 deploy/ 的实际形态手册。修改 Next.js 代码前先读 node_modules/next/dist/docs/ 中相关版本指南。

需求冲突遵循用户最新明确要求、PRD、实施参考的顺序；历史测试和旧部署说明不构成当前证据。实现细节以实际代码和锁文件为准。将阶段状态与证据集中记录在 docs/all-subject-rag-progress.md，避免重复编写产品需求。

检查工作区、HEAD、分支、远端、已有变更、工作流触发和本地可用服务。保留用户已有未提交改动，优先使用专用 codex/ 分支及独立工作树。仅暂存本任务文件，不进行清理、硬重置或强推。若当前阶段已有完成代码，核对证据后补缺，避免重写。

## B. 执行范围

完整实施方案见 docs/all-subject-rag-development-plan.md 第 2—3 节。依次执行：

- W0：现状与硬编码盘点、模型/接口/迁移映射、供应商与数据库条件、样本和数值验收阈值、阶段任务台账。交付后立即进入 W1。
- W1：统一可扩展学科字典，贯通用户意向、证书、岗位、解析审核、发布、匹配、当前/历史筛选和关注；兼容旧语文资料及未知/歧义。
- W2：基于现有官方材料链路实现文档/版本/片段/原文定位、向量存储、异步索引与管理员状态/重试，验证权限与撤回。
- W3：公告详情问答、范围过滤、中文关键词与语义混合召回、重排、上下文、生成、后端引用校验、错误恢复和反馈；完成真实供应商联调。
- W4：多角色、更新撤回、权限、任务恢复、限流预算、国内依赖与旧功能回归；隔离真实部署综合验收和回退验证。
- W5：带地区/年份/适用对象的政策检索，以及至少一个现有覆盖之外的可核验官方来源完整链路；维护全国来源扩展积压与真实覆盖。七天观察及全面扩源仍按真实进度说明。

沿用现有技术架构；选用 PostgreSQL/pgvector 和服务端模型接口，不先搭工作流平台。供应商、模型和境内 endpoint 按官方文档和实际账号验证后固定，Embedding/Rerank/生成分别配置。控制改动范围，复用已有安全、任务、解析、审核与存储能力。

## C. 每阶段必须执行的闭环

1. 更新台账：需求、任务、受影响文件、依赖、测试和当前状态。
2. 实现完整调用链，补必要的有效测试和迁移；不通过降低测试断言或删用例来制造通过。
3. 运行相关单元/集成测试及当前脚本定义的 lint、类型检查、构建和必要浏览器流程。涉及数据库时验证真实隔离数据库迁移；涉及供应商时模拟和真实验证分开。
4. 自检完整差异及上下游：需求覆盖、兼容、权限、未知和异常路径、版本有效性、资源预算与隐私。发现问题先修复并重跑受影响检查。
5. 更新本阶段证据：命令、退出状态、版本、样本、结果、缺口；检查暂存差异、锁文件、迁移、凭据和无关改动。
6. 提交本阶段明确文件并普通推送到专用开发分支。用户已授权阶段完成后的提交与推送，无需每阶段重复确认；该授权不包含合并默认分支或生产部署。
7. 查询同一 SHA 的远端 CI 与镜像发布（若工作流适用）；失败修复后重新提交推送。“未触发”“无法查询”“排队中”不是通过。通过后自动继续下一阶段。

如果推送失败，保留本地提交和证据；查明鉴权/网络/冲突，安全修复可自行处理。平台故障或缺必要授权时明确阻塞及最少用户动作，不假装门禁已通过，不越过依赖门禁。可以继续独立分析或不依赖该阻塞的任务，但阶段不能虚报完成。

## D. API 和外部依赖

你负责接口代码、适配、配置模板、错误恢复、脱敏日志和真实联调。已有安全环境变量时直接使用，确认是否存在即可，不打印值。用户需要提供账号开通、实名/付款、模型权限、预算和安全注入的 Key；这些是外部条件，不是让用户手写接口。

在 W0 尽早集中说明缺少的条件，同时继续独立工作。没有 Key 时可实现并测试适配器，但真实向量/重排/生成测试保持阻塞，功能默认关闭或明确不可用。不得伪造供应商成功结果，不提交凭据，不使用未经授权账号或产生未批准费用。

数据库使用隔离实例和增量迁移。若系统权限或真实服务不可用，先诊断和准备不受阻部分，如实记录缺口。任何生产操作、默认分支合并、付费采购另需明确授权，不把 Git 推送当成这些操作的授权。

## E. 全阶段完成后的验收

按实施方案第 5 节，在固定提交的真实隔离前后端、PostgreSQL、Redis、Worker 和真实模型 API 上执行完整端到端流程。使用浏览器验证用户和管理员路径，模拟模式不能替代真实业务验收。

必须串联真实材料导入、解析、审核、发布、索引、多学科画像、匹配、问答、引用、关注/材料/日程、补充公告、变化重算、纠错、撤回和权限隔离。覆盖移动/桌面、无答案、跨岗位、跨地区年份、供应商失败及文档提示注入。运行必需的全量检查与固定评测集，修复发现的问题后重测受影响链路。

输出 docs/all-subject-rag-final-acceptance.md，按实施方案报告清单提供需求追踪、模块 SHA、CI 链接、测试环境、命令/结果、真实 API 证据、评测指标、迁移/回退、覆盖及剩余阻塞。新增能力有任何关键失败时结论为未完成，给出影响和下一步；不能将 skipped、模拟通过或历史报告写成当前真实验收成功。

提交并推送报告，核对最终远端状态。最终向用户简要说明完成内容、分支/最终 SHA、验收报告路径、是否操作生产、剩余事项和必要用户动作。长任务交接时依靠阶段台账续接，不丢失已验证证据，不反复重做已完成阶段。

现在从 W0 开始执行，持续推进到可完成的最终验收；仅在真正需要外部输入、权限或不可恢复阻塞时停下并明确说明。
