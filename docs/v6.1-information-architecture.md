## 1. 设计约束

- 主导航只有三个入口：**机会 / 日程 / 备考**；设置、通知、资料、账号进入头像菜单或上下文页面。
- 一屏一个问题、一个主要行动；结论优先，证据渐进展开。
- 每个核心页面采用三层信息结构：
  1. **第一层：结论与下一步**——我能否考虑、接下来做什么；
  2. **第二层：主要依据与风险**——为什么这样判断、还有什么不确定；
  3. **第三层：完整来源与细节**——公告原文、岗位表、核对时间、变化记录、纠错入口。
- 首屏禁止：仪表盘、统计卡阵列、能力雷达、排行榜、月历、常驻复杂筛选栏、多个同等级按钮。
- 关键状态同时用文字和图标表达，不能只靠颜色；移动端触控目标足够大，320px 宽度无横向滚动。
- 视觉：中性背景 + 一个主蓝色；绿/黄/红只表示状态；减少阴影、渐变、彩色徽章与装饰图标。

## 3. 首次使用旅程

```text
价值首页
  → 五组基础画像（一次一组，可返回，答案保留）
      1. 可接受地区（必须接受 / 优先 / 可以考虑）
      2. 最高学历和学位
      3. 毕业证专业全称
      4. 毕业时间与当前就业状态
      5. 教师资格证状态、学科、学段 + 对用工形式的接受度
  → 初步匹配结果（/preview，访客可见）
  → 按需补问条件（年龄/户籍/社保/经历，仅当某机会需要，先说明原因与影响范围）
  → 关注机会（此时才要求登录；登录后访客数据幂等迁移）
```

规则：

- 年龄、户籍、社保、工作经历**不进基础画像**，遵循“先给结果，再补信息”。
- 报考学科非语文：明确提示该学科尚未开放、可留下意向，不生成虚假匹配。
- 首次结果不出现 7 天备考计划；备考只在主要目标确定后出现。
- 不让用户永久自我标记“应届生”：记录毕业时间、就业、社保等事实，应届与否按具体公告判断。

## 4. 机会模块

### 4.1 机会列表 `/opportunities`

**第一层（首屏）**

- 一句结论：当前为你找到 N 个初步符合的语文学科机会（覆盖范围与“最后更新时间”同时可见，未覆盖 ≠ 没有招聘）；
- 一张优先机会卡：地区/报考单元、用工性质、学段、招聘人数、报名截止、一句话匹配依据、当前下一步；
- 一个主按钮跟进优先机会。

**第二层（向下展开或次级分组）**

- “初步符合”列表；
- 按缺失条件分组的入口，例如“另有 8 个机会，补充户籍信息后判断”；
- “建议人工确认”“明确不符合”作为二级分组，明确不符合默认不进主推荐但可查看原因。

**第三层（详情页内）**：官方公告与岗位表链接、字段出处、最后核对时间、版本变化记录、纠错入口。

机会卡内容预算（上限 6 项 + 1 个行动）：地区与报考单元 / 用工性质 / 学段 / 招聘人数 / 匹配状态（文字）/ 报名截止 / 一句话依据。

排序（确定性、可向用户解释）：地区偏好 → 资格确定程度 → 事业编优先于其他用户接受的官方用工形式。“即将截止”只做标签与日程提醒，不默认等同于更适合。

### 4.2 机会详情 `/opportunities/[id]`

- 第一层：四档结论之一（初步符合 / 补充信息后判断 / 建议人工确认 / 明确不符合）+ 唯一下一步；“初步符合”不得写成“保证可以报名”。
- 第二层：三组条件清单——已满足 / 不确定（需要补充或人工确认，逐项说明原因）/ 明确不满足；以及报名时间与关键材料。
- 第三层：官方原文锚点（链接、页码、工作表/单元格）、公告版本与核对时间、变更记录、纠错。
- 报考单元与任教学校必须分清：报名对象是区县/岗位组/学校中的哪一种、录取后如何分配（直接报学校 / 按成绩择校 / 统一调配）。

### 4.3 关注与报名推进状态

`考虑中 → 准备报名 → 已报名 → 已结束／已放弃`

- 收藏/关注不自动等于“准备报名”；
- 状态变化保留时间与来源；
- 可同时关注多个机会，不强迫过早单选；放弃一个不影响其他机会与备考目标；
- 可把一个关注机会设为**主要备考目标**，其余自动成为备选，不生成多套冲突计划。

## 5. 日程模块 `/schedule`

- 第一层：只突出“下一件不能错过的事”（最近且需要行动的一项）+ 主行动；没有待办时给明确空态，不制造虚假紧迫感。
- 第二层：按关注机会分组的时间线：公告发布 → 报名开始/截止 → 资格审核 → 缴费截止 → 准考证打印 → 笔试 → 成绩查询 → 面试节点。
- 第三层：单事件来源、官方原文时间、变更记录。
- 不默认展示月历；时间未定一律显示“待官方通知”，禁止推测日期。
- 通知强度三档：必须处理（即将截止、条件变化、岗位取消）／建议处理（材料未备、主目标未定）／普通信息（公告新增、时间待定）；普通信息不得与截止风险同视觉强度。
- 考试时间冲突主动提示，但不替用户自动放弃任何机会；用户可对单个机会关闭提醒。

## 6. 备考模块 `/study`

进入门禁（不满足时第一层给“下一步”，不生成计划）：

1. 已选择一个主要备考目标（来自已关注机会）；
2. 该目标的考试内容与来源已核对；未核对时给具体的信息查找任务，不编造科目与日期。

首屏：今天**只做这一项**任务，含五要素——做什么、用什么、预计多久、怎样算完成、为什么先做。今日任务总时长不得超过当日可用时间。

第二层：快速自评（薄弱/一般/熟悉三级，均带行为说明）或约 10 分钟短诊断（仅覆盖核心模块，只用于首周分配）；7 天主题与逐日任务；反馈入口（做完了 / 做了一部分 / 今天没做，三次点击内完成）。

第三层：资料适用性、公共资源依据、考情来源与版本、计划版本历史。

复用现有 PlanEngine / ReplanEngine / 反馈规则：未完成不把欠账全堆到次日；时间不够给“今天先做这一项”；更换主要目标前先说明计划会怎样变化。PRD P1 的多目标时间分配不在本轮。

## 7. 状态词表（用户可见文案统一）

| 场景 | 状态文案 |
|---|---|
| 资格总结果 | 初步符合 / 补充信息后判断 / 建议人工确认 / 明确不符合 |
| 单项条件（内部值不外显英文） | 已满足 / 信息不足，补充后判断 / 存在歧义，建议向招聘单位确认 / 不满足 |
| 数据事实层级 | 公告原文事实 / AI 提取候选（待审核）/ 已人工核对 |
| 关注状态 | 考虑中 / 准备报名 / 已报名 / 已放弃 / 已结束 |
| 备考目标 | 主要目标 / 备选目标 / 已完成考试 / 已取消 |
| 时间未定 | 待官方通知 |
| 加载与异常 | 加载中 / 暂无内容（说明下一步）/ 暂时加载失败（可重试）/ 权限不足 |

所有状态必须覆盖成功、加载、空数据、失败、权限不足五种界面；关键结论不能只靠颜色。

## 8. 演示环境与受邀环境的 IA 差异

| 维度 | demo（公开演示） | invited（受邀试用，落地后） |
|---|---|---|
| 数据 | localStorage，明确横幅提示 | 服务端持久化，无演示横幅但有测试版说明 |
| 登录 | 内置演示账号一键填充 | 管理员预建账号，真实服务端会话 |
| 后台 | `/admin` 整体关闭 | 对工作人员开放，权限服务端校验 |
| 公告 | 预置 seed（六种匹配场景）+ 模拟提取 | 人工提交、机器候选、人工审核后发布 |
| 通知 | 本地模拟状态，不发送 | 站内事件真实生成；不接短信/微信 |
| 重置 | 设置页“重置演示数据” | 提供退出、注销与删除测试数据入口 |

两种环境使用同一套页面结构与状态词表；任何环境下 AI 候选与官方事实视觉上必须可区分。
